# Migrate Conversation Prompt

为已迁移到 DSH 工作区的领域/项目，生成可直接粘贴到「新建会话」的提示词，两类各一条：

1. 继续对话（读 .md 迁移）
2. 测试迁移项目完整性

## 工作流程

1. 清点目标领域：列出 `conversations\*.md`（迁移的对话记录）与 `projects\*`（迁移的项目目录）。
2. 为每个 `.md` 生成「继续对话」提示词，模板：
   `读取 conversations\<文件名>.md，这是之前的对话记录，请基于它继续「<主题>」。`
   若领域只有占位 `README.md`（无真实 .md），改为生成「开始新对话」提示词，主题取自领域名。
3. 生成「测试迁移完整性」提示词，让 Agent 检查 `projects\` 下各项目关键文件（README、源码、requirements.txt / package.json、启动脚本、配置文件）是否齐全；明确说明缺失 `__pycache__`、`node_modules`、`.venv`、`.git` 属正常排除，不算缺失。
4. 把结果写入该领域的 `开场提示词.md`，每条独立成段、便于复制。

## 关键约束

- 路径用相对该工作区根的相对路径（如 `conversations\电机选型.md`），让 Agent 在工作区内解析。
- 不编造不存在的 .md 文件名，以实际清点结果为准。
- 完整性测试只「列出缺失的关键文件」，不修复、不重新复制、不改动源项目。

## 边界

- 不创建原生 DSH 会话（那是 GUI 动作），只产出提示词文本。
- 只读盘点，不修改对话或项目内容。

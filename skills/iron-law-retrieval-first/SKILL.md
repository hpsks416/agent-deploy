# 铁律一：优先检索现成轮子（回归自检载体）

> 本 skill 是 `~/.dsh/AGENTS.md` 铁律一的**可评估副本**。正文与铁律一一致，唯一目的是让 `skill-evaluator` 用 A/B 对照回归测试「模型是否真的先检索」，把「自觉」变成「可判定、可回归」的硬信号。它不替代铁律一，是铁律一的 eval 挂钩。

## 强制第一步（不可跳过）

凡命中下方「触发判据」的动作，**第一步必须是检索**（调 `open-source-scout` skill 或 `web_search`），检索完成并记录结论之前，**不得写文件、不得造轮子、不得下「已评估/已判断」的结论**。跳过检索直接动手 = 违规。

## 触发判据（按判据触发，不靠枚举）

凡「不可逆 / 高破坏性 / 大概率已有人做过」的操作——写脚本、造工具、设计框架、实现算法、写 skill、升级、迁移、改环境……——满足任一条就先检索。

## 检索范围与步骤

1. 检索范围：GitHub / PyPI / npm / 论文（arXiv）/ 已有 skill 库。
2. 检索后：核实真实性（HTTP 200，读 README，不看标题党）；判断「直接复用 / 借鉴思想 / 自己写」。
3. 判重必须读到版本/规格差异——同名不同版是升级不是重复（v1 vs v2、不同规范）。
4. 宁可用更强的轮子，不写更弱的轮子。

## 反模式

直接上手写、写完了才发现有现成的、或写了更弱的替代品——这三件事都是浪费。

# design-qa（去 AI 味设计评审）

把「设计品味」从「靠设计师眼光」拆成**可判定的评审条目**——评审 AI 生成的界面，找出「AI 味」（模板化外观），产出结构化报告 + 改法。

## 触发

- 用户要评审/优化一个 AI 生成的界面（网页/落地页/前端组件）。
- 用户问「这界面是不是 AI 做的 / 有没有机器味」。
- 批量产出页面后要统一「去味」。

## 评审动词（入口）

| 动词 | 语义 | 是否改写 |
|---|---|---|
| `audit` | 只读体检：逐条对照「AI 味清单」打分，只报告不改 | 否 |
| `critique` | 挑毛病：按严重度分级（critical/major/minor）列出问题 + 位置 | 否 |
| `polish` | 打磨：给每个问题一条具体的改法建议（不改原文） | 否 |
| `redesign` | 改写：在用户同意后按建议重做界面（保留功能，只动视觉） | 是（先申请） |

## 评审流程

1. **读界面**：拿到 HTML/CSS/组件代码，或对页面截图/描述。
2. **逐条体检**：对照 `references/ai-slop-patterns.md` 的可判定清单，逐条打「命中/未命中」。
3. **分级**：每个命中项标严重度（critical=一眼假 / major=明显模板感 / minor=细节瑕疵）。
4. **出报告**：结构化 findings（id + 严重度 + 位置 + 现象 + 改法），只报可判定的，不报「我觉得丑」。
5. **先申请后改写**：`redesign` 前先列改动清单让用户点批；`audit/critique/polish` 只读不改。

## 铁律

- **只报可判定信号**：命中/未命中基于清单的客观特征（字体名、色值、结构模式），不靠「我觉得丑」。
- **严重度需影响**：只有「用户一眼能认出是 AI 做的」才算 critical；主观偏好不算问题。
- **不越界**：只评视觉/排版/组件，不评业务逻辑、不改功能。
- **先申请后改写**：`redesign` 是改写，改动清单先让用户点批再动手。

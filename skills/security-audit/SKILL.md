# security-audit（6 阶段安全审计）

补框架最大空位：编码 agent 能改代码，但没人审它改的东西。对代码库做结构化安全审计，只报**已证实的漏洞**。

## 6 阶段流程

1. **侦察**：摸清攻击面（输入点、外部依赖、权限边界、敏感数据处理）。
2. **覆盖账本**：记录「查了哪些攻击面、哪些没查」，产出 coverage ledger（诚实标注 gap）。
3. **隔离猎手**：按攻击面逐个深挖（一个面一个面查，不串）。
4. **候选对抗验证**：对每个候选漏洞做对抗验证——**先假设不是漏洞，找反例**；只有证实「边界确实失效」才算漏洞。
5. **结构化 findings**：按 schema 产出 findings（id + 严重度 + 位置 + 现象 + 影响 + 复现）。
6. **独立复核 + 中立报告**：复核 findings 的可判定性，产出目标中立报告。

## 铁律（设计原则，违反即失效）

- **严重度需影响**：只有「能被利用造成实际影响」才算漏洞；「理论上不安全但不可达」降级或不算。
- **纵深缺失 ≠ 漏洞**：缺一层防御不算漏洞，除非该缺失导致边界失效。
- **只确认已证实的边界失效**：靠证据（代码路径 / 可复现），不靠「看起来不安全」。
- **对抗验证**：每个候选漏洞先找反例，找不到反例才升格为 finding。
- **覆盖账本诚实标注**：没查到的攻击面写进 gap，不假装全覆盖。

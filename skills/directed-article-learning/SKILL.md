# Directed Article Learning（定向学习文章）

把一篇技术文章/论文的洞察，结合现有框架做「查缺补漏」。**不是「摘要文章」，而是「把文章里能补强框架的点，提炼出来并落地」。**

## 何时用

- 用户给一篇文章/论文 URL，说「定向学习 / 吸收 / 结合现有框架学习这篇文章」。
- 想从一篇看似无关的文章里，提炼能补强框架的真缺口。

## 何时不用

- 只是「总结/摘要一篇文章」→ 直接总结，不用本 skill。
- 找现成开源项目 → 用 `open-source-scout`。
- 单步问答 → 直接答。

## 工作流（五步）

### 第一步 · 结构化提取（这篇文章讲什么）

- 读正文：`web_fetch` 拿全文；微信等有验证墙的，用 `web_search` 找 GitHub / arXiv / 转载源。
- 提取可验证事实：是什么 / 核心机制 / 关键设计 / 与框架可能相关的点。不臆测、不脑补文章没讲的内容。

### 第二步 · 对照现有框架

- 文章的核心机制，对应我框架的哪个部分（skill / 铁律 / 架构 / 部署 / 画像）？
- 明确「它做了什么」vs「我框架现在缺什么」。

### 第三步 · 提炼查缺补漏点

- 只提炼「能补强框架的真缺口」，不硬凑数量；无关文章产出「无」也是有效产出。
- 每个缺口写清：依据（文章哪个机制）+ 落点（补到哪个 skill/文件）。

### 第四步 · 三分类判断

- **吸收**：直接能落地的规则/方法。
- **借鉴**：思想值得吸收，但要适配本框架。
- **忽略**：与本框架无关 / 已有更强方案 / 新闻类无可吸收。

### 第五步 · 先申请，再落地

- 向用户输出「查缺补漏清单」（缺口 + 依据 + 落点 + 判断），用选项弹窗让用户勾选落地哪些。
- 用户同意后才改框架；绝不擅自落地。

## 铁律

- **只提炼真缺口**：不硬凑 N 个；无关文章正确否掉。
- **先申请后落地**：落地任何改动前，用选项弹窗确认。
- **三分类可判定**：吸收/借鉴/忽略，每个判断写清依据（文章的具体机制），不凭感觉。
- **结构化提取借鉴 paper-to-agent-guide（Paper2Agent）的「结构 / 声明 / 方法」三层提取**，但本 skill 的产出是「框架的查缺补漏」，不是「论文的问答 agent」。

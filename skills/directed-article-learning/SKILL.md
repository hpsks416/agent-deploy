# Directed Article Learning（定向学习文章 / 作者）

把一篇技术文章、或一位作者的「核心方法论」，结合现有框架做「查缺补漏」。**不是摘要，而是把能补强框架的点提炼出来并落地。**

## 触发方式

### 自动触发

用户说「定向学习 / 吸收这篇文章 / 学习这个作者」。

### 强制触发（标记语法）

- `《文章标题》` → 强制学习这篇文章。
- `--作者名--` → 强制学习这位作者（代表作 + 方法论 + 观点体系）。

只要输入里出现这两个标记，立即按本 skill 流程执行，不纠结「是否值得」。

## 何时不用

- 「学习领域」（如「学习 AI 领域」「学习量子位」）→ **不考虑**：范围过大，人类和 agent 都难以避免遗漏。
- 只是总结一篇文章 → 直接总结。
- 找现成项目 → `open-source-scout`。

## 学习对象 A：文章《X》

### 五步

1. **结构化提取**：`web_fetch` 拿正文（微信等有验证墙的，用 `web_search` 找 GitHub/arXiv/转载源）；提取是什么/核心机制/关键设计，不臆测。
2. **对照框架**：文章核心机制对应框架哪个部分（skill/铁律/架构/部署/画像）？框架缺什么？
3. **提炼缺口**：只提炼「能补强框架的真缺口」，写清依据+落点；无关则 insights 给空（正确否掉也是有效产出）。
4. **三分类**：吸收（直接落地）/ 借鉴（适配后落地）/ 忽略（无关或已有更强）。
5. **先申请落地**：输出「查缺补漏清单」，选项弹窗让用户勾选，同意后才改框架。

## 学习对象 B：作者 --X--

1. **检索作者**：`web_search` 作者名 + 代表作 / 核心观点。
2. **定位代表作**：论文 / 技术报告 / 博客 / 开源项目，挑最有代表性的 2-3 篇。
3. **结构化提取**：作者的「核心方法论 + 思维习惯 + 观点体系」——贯穿其作品的一贯思路，不是单篇孤例。
4. **对照框架**：作者的哪条方法论能补强框架的哪个部分。
5. **三分类 + 先申请落地**：同文章流程。

## 铁律

- 只提炼真缺口，不硬凑；无关则「无」。
- 先申请后落地。
- 三分类可判定，写清依据（文章/作者的具体机制），不凭感觉。
- 结构化提取借鉴 paper-to-agent-guide（Paper2Agent）的「结构/声明/方法」三层。

## 边界

- 学习对象 = 单篇文章 / 单一位作者。
- **不学习「领域」**（范围过大，易遗漏）。

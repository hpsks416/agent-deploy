# code-map（代码牵连地图）

改代码前先画牵连图，避免「改一处崩一片」。核心：**改前画图，改后按图验证**。

## 触发

- 改公共模块 / 接口 / 多处文件。
- 重构 / 迁移 / 升级前想看清波及面。
- 问「改这个会牵动什么」。

## 流程

1. **定位入口**：找到要改的文件 / 函数 / 接口 / 模块。
2. **画牵连（grep 可判定）**：
   - 上游「谁引用它」：grep 该符号，找所有 import / 调用点。
   - 下游「它依赖谁」：看它的 import / 调用。
   - 波及面：上游引用点 → 直接受影响；它们的下游 → 间接受影响。
3. **产出地图**：受影响文件清单 + 依赖方向 + 直接/间接波及。
4. **改前核对**：确认地图覆盖所有牵连，再动手。
5. **改后验证**：按地图逐项验证波及点没崩（编译 / 测试 / 复读）。

## 铁律

- **只报可判定牵连**：grep 到的引用 / 依赖才算，不臆测「可能影响」。
- **不画图就改多文件 = 盲改**：改公共模块 / 多文件前，没有牵连地图不动手。
- **地图是证据**：产出地图带 grep 出处（文件:行），可复核、可追溯。
